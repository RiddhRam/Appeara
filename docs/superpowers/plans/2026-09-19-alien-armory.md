# Alien Armory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Hackathon mode: tasks list files, interfaces and tests; code is written directly in the files (not duplicated here).

**Goal:** Single-player Quest Link VR wave shooter where spoken weapon descriptions become assembled weapons, and the alien mothership adapts to what the player uses.

**Architecture:** Pure C# core (spec parsing/clamping, damage table, combat log, adaptation rules) with EditMode tests; MonoBehaviour layer (rig, weapons, enemies, waves); AI/audio services behind interfaces with mock fallbacks. Scene content is generated by an editor menu into one `Armory` root in `SpaceStation.unity`.

**Tech Stack:** Unity 6000.3.13f1 URP, OpenXR (Meta runtime via Quest Link), Input System (only), UnityWebRequest + `Awaitable`, JsonUtility, OpenAI Chat Completions (structured outputs) + Audio Transcriptions, ElevenLabs TTS + Sound Generation (PCM output).

**Spec:** `docs/superpowers/specs/2026-09-19-alien-armory-design.md`

## Global Constraints

- Keys only from `UserSettings/ArmoryKeys.json` (gitignored); values trimmed; missing → mock mode + warning.
- Defaults (verified 2026-09-19): weapon/mothership model `gpt-5.4-mini` with `reasoning_effort: "none"` (0.9–1.7 s);
  transcription `gpt-4o-mini-transcribe`; ElevenLabs TTS `eleven_flash_v2_5`, `output_format=pcm_22050`
  (16-bit mono LE); Ship AI voice Alice `Xb7hH8MSUJpSbSDYk0k2`; Mothership voice Callum `N2lVS1w4EtoT3dr4eOWO`
  (pitched down in Unity).
- Input System only (`activeInputHandler: 1`) — no `UnityEngine.Input`.
- No Newtonsoft; request JSON built by hand, responses parsed with JsonUtility.
- The LLM never produces code; all numbers clamped + power budget in `WeaponSpecParser`.
- Every network call has a timeout and a fallback; firing is never blocked by a pending call.
- Don't touch teammates' files except adding the `Armory` root to `SpaceStation.unity`.

## Tasks

### Task 0: Editor command bridge
- Create `Editor/ArmoryCommandBridge.cs`: `[InitializeOnLoad]`, polls `Temp/armory-command.txt` each second;
  commands `refresh`, `tests`, `setup`, `play`, `stop`; writes `Temp/armory-result.txt` (compile errors
  captured via `CompilationPipeline.assemblyCompilationFinished`; tests via `TestRunnerApi`).
- Verify: user focuses Unity once; `refresh` round-trips.

### Task 1: Core logic (TDD)
- `WeaponSpec` (JsonUtility DTO, strings) → `WeaponSpecParser.Parse(string json) : ParsedWeapon` with enums,
  clamps (fireRate 0.5–15, projectileCount 1–12, spreadDeg 0–45, speed 5–80, damage 1–100), power budget
  (each modifier/onHit beyond the first costs 15% damage), unknown enum → default, bad JSON → `null`.
- `DamageTable.Multiplier(EnemyKind, Payload, Mods, Resistances)`.
- `CombatLog.Record(Payload, Mods, float dmg)`, `TopPrimitive()`.
- `AdaptationRules.Fallback(CombatLog) : Counter[]`, `Counter` parse from strings.
- `WavPcm.EncodeWav(float[] samples, int hz)`, `WavPcm.Pcm16ToFloats(byte[])`.
- `MockWeaponInterpreter.Interpret(string)` keyword → spec JSON (offline mode).
- Tests for each; run via bridge `tests`.

### Task 2: Rig + arena + default gun (playable step 1)
- `ArmoryRig`: port QuestLinkRig pattern; exposes `RightAim`, `LeftHand`, button states
  (trigger, grip-left PTT, B drop, X recenter, sticks); desktop fallback (mouse look/aim, LMB, T, 1–5).
- `TeleportController` + `TeleportPad` (left stick forward → ray, release → nearest pad to hit point);
  right stick snap turn 45°.
- `Weapon` + `Projectile` + default machine gun spec; `Enemy` (grunt) walks to `StationCore`.
- `ArmorySceneSetup` menu builds `Armory` root: arena floor, core, 4 pads, rig, spawner, HUD.

### Task 3: Assembler + behaviours (playable step 2)
- `WeaponAssembler.Build(ParsedWeapon, Transform hand)` parts/colour; `Projectile` handles homing,
  piercing, bouncing, sticky, proximity, thrown gravity; `Explosion` splash; chain; slow; `BeamEmitter`.
- Desktop keys 1–5 load mock-interpreted canned prompts.

### Task 4: OpenAI (playable step 3)
- `OpenAiClient.InterpretWeapon(request, waveContext)`, `Transcribe(wav)`, `Adapt(logSummary)`.
- `PushToTalk` records mic (prefers device containing "Oculus"/"Headset"), `ShipAI` pipeline with
  fabrication hologram; `T` text box on desktop.

### Task 5: Enemies, waves, mothership, boss (playable step 4)
- Kinds Grunt/Swarm/Armored/Fast/Shielded/Boss; `WaveDirector` scripted waves 1–5 + breaks;
  `Mothership` applies counters (armor, shield, dodge, teleport, spread, rush, intercept, reflect, resist:X);
  boss re-adapts every 20 s.

### Task 6: ElevenLabs (playable step 5)
- `ElevenLabsClient.Speak(text, voiceId)`, `GenerateSfx(prompt, seconds)` → AudioClip from PCM, disk cache.
- Ship AI + mothership lines voiced; weapon fire/impact SFX swap in when ready.
