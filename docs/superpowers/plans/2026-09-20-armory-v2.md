# Alien Armory v2 — implementation plan

**Spec:** `docs/superpowers/specs/2026-09-19-armory-v2-design.md`
**Branch:** `armory-vr`. Each task ends compiling, with EditMode tests green and a bridge/MCP verification.

Order is by risk: the voice bug blocks the whole demo, so it goes first; story polish goes last.

---

### Task 1 — Voice capture fix + mic diagnostics (blocks demo)
- `MicCapture` class extracted from `ShipAI`: device selection with preference order, start/stop, level metering,
  relative-threshold trim, gain normalisation, per-attempt log line.
- Comms card: live level meter while the grip is held; specific failure text after release.
- `AiSettings.MicDeviceContains` override; remembered working device in PlayerPrefs.
- Bridge command `miclevels` + menu **Armory → Mic Levels** (2 s per device, prints peak/RMS).
- Tests: trim/normalise/too-short decisions as pure functions.
- **Headset check:** meter moves while speaking; a transcript appears; `miclevels` names a working device.

### Task 2 — Locomotion: smooth move + stand-on translocator pads
- `Locomotion` rewrite: left-stick head-relative movement (2.6 m/s), comfort vignette, snap/smooth turn setting.
- `TeleportPad` gains `LinkedPad`; standing on a pad fills its ring over 0.6 s, then moves the rig; stepping off
  cancels; a light arc shows each pair. Remove aim-teleport.
- Invisible boundary wall at the railing.
- **Check:** desktop WASD-equivalent (stick emulation) walk onto a pad → translocate; pads visible in captures.

### Task 3 — Armory phase + multi-turn conversation
- `WaveDirector` gains an `Armory` state: no spawns, core repairs 2 HP/s, wave starts on "ready"/A button.
- `ShipAI` keeps a 6-turn transcript; new OpenAI schema returns `{reply, buildWeapon?, weapon?}` so ARIA can ask
  questions and only fabricate on confirmation.
- ARIA briefing line at phase start (hive counters + suggestion).
- **Check:** desktop text mode conversation: ask "what's coming?", get a briefing; "make me something for shields",
  get a question or a weapon; say "ready" to start the wave.

### Task 4 — Elements, debuffs, budget, tuning
- Core: `Element` replaces `Payload` (kinetic/fire/plasma/electric/cryo/corrosive) with status effects
  (burning, weakened, melting, shocked/stunned, chilled/brittle, etched) in `StatusEffects`.
- `WeaponBudget`: costs per element/modifier/RPM band/count/damage; `Budget(waveIndex)`; re-cost and trim with a
  player-facing message. Prompt includes the budget.
- Wrist "tuning" row during ARMORY: RPM/damage/count within budget, thumbstick or voice.
- Tests: budget costing, trimming order, status stacking, damage with debuffs.
- **Check:** overspec prompt ("infinite damage rocket that chains ten times") comes back trimmed and legal.

### Task 5 — Sketch board
- `SketchBoard` during ARMORY: 384×384 render texture on a holo board, right-trigger strokes (element colour),
  undo/clear; PNG base64 attached to the next OpenAI request as vision input, and passed as the reference image
  for the gpt-image blueprint.
- **Check:** draw a shape in desktop mode, ask for "this, but electric", spec reflects the sketch; blueprint uses it.

### Task 6 — Tutorial (fabricator induction)
- `Tutorial` state machine with schematic controller visuals, checklist panel, per-step completion conditions,
  skip option. Runs in the corridor before wave 1.
- **Check:** each step advances only on the real input; skip works.

### Task 7 — Story frame + intro
- Shuttle approach beat (cockpit shell, station exterior, ARIA/Kestrel VO), dock, corridor, atrium reveal.
- Narration written once via OpenAI, voiced via ElevenLabs, cached; subtitles; skippable.
- Hive/ARIA between-wave banter draws on the story context.
- **Check:** full run from intro to wave 1 without input beyond the tutorial steps.

### Task 8 — Boss handoff
- Hive Avatar stub: teammates' alien model, walk-in, weak points, plating visual, telegraph helper API so Astra can
  attach animations/attacks. Document each attack's hook in the spec's boss section.
